# ТЗ: Битрикс24 для ремонтной компании

## Цель

Клиенты и сделки ведутся в одной системе, ни одна заявка не теряется, а руководитель видит, на какой стадии каждый объект.

## Процесс

1. **Заявка.** Менеджер связывается с клиентом в течение 15 минут.
2. **Замер.** Менеджер согласует дату и подтверждает её с клиентом, замерщик выезжает на объект.
3. **Смета.** Менеджер готовит смету в течение 2 дней после замера и согласует её с клиентом.
4. **Договор и предоплата.** После согласования сметы заключается договор, затем поступает предоплата.
5. **Работы.** Менеджер назначает бригаду и дату начала в течение дня после предоплаты.
6. **Сдача.** Приёмка с клиентом, подписание акта, получение остатка оплаты.

На любом этапе клиент может отказаться: сделка уходит на стадию «Отказ» с указанной причиной.

## Требования

### Воронка
Стадии: Новая заявка, Связались, Замер назначен, Замер проведён, Смета на согласовании, Договор, Предоплата получена, Работы идут, Сдача объекта, Объект сдан, Отказ.

### Поля сделки
| Поле | Тип | Значения |
|---|---|---|
| Тип объекта | список | Квартира, Дом, Офис, Коммерческое помещение |
| Вид ремонта | список | Косметический, Капитальный, Дизайнерский, Черновая отделка |
| Площадь, м² | число | |
| Адрес объекта | строка | |
| Дата замера | дата и время | |
| Причина отказа | список | Дорого, Выбрали другую компанию, Перенесли ремонт, Не вышли на связь, Не наш объём работ |

### Автоматизация
- При входе на стадию ответственный получает задачу со сроком.
- Завершение задачи согласования сметы переводит сделку на стадию «Договор».

### Перенос данных
- Источник: таблица Excel с клиентами.
- Один контакт на телефон или почту, повторы сливаются.
- Статусы из таблицы сопоставляются со стадиями воронки.
- Строки, которые нельзя перенести, попадают в отдельный файл с причиной.
- Повторный запуск не создаёт дублей.

## Критерии приёмки

1. Новая сделка на первой стадии получает задачу со сроком 15 минут.
2. Завершение задачи согласования переводит сделку на «Договор», завершение другой задачи не меняет стадию.
3. Сумма строк сходится: перенесённые клиенты + слитые повторы + отклонённые = все строки с данными.
4. Повторный запуск переноса создаёт 0 контактов и 0 сделок.
